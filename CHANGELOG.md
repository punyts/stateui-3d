# Changelog

## Unreleased
- **`label3d`** (G3.6b of the graphics epic 3): new `labels.ts` (`Labels`, `labelText`, `labelFontSize`, `labelCanvasSize`, `labelFont`, `LABEL_FONT_PX`, `LABEL_LINE_HEIGHT`, `LABEL_PADDING`, `LABEL_MAX_WIDTH`, `LABEL_MAX_CHARS`, `DEFAULT_LABEL_FONT_SIZE`, `MAX_LABEL_FONT_SIZE`, `DEFAULT_LABEL_COLOR`, `DEFAULT_LABEL_FONT`, the type `LabelHooks`). A `label3d` draws its `_text` with `fillText` on a canvas (never markup) in the page font (the host's computed `font-family`; new option `readFont`) and its `color`, else the new `Scene3dSettings.labelColor`, else black, as an sRGB `CanvasTexture` on a `Sprite` that faces the camera, with its own quad whose bounds are a cube as wide as the label. `fontSize` (scene units, default 0.3) sizes it; the sprite is 1.4 em high. The canvas is drawn again only when the text, the font or the colour changes (`restyle`, a `labelColor` change, a web font that finishes loading), as a new texture with the old one freed; removing the node or emptying the text frees the texture, material and quad. An empty text draws nothing and reports nothing; a text is cut at 512 characters and 2,048 texels. `SceneGraph` takes the label hooks as a fourth argument and has `labels`; `Scene3dInfo.labels` counts the labels drawn. Tests: `src/labels.test.ts` (Node, a fake canvas), `test/label.browser.test.ts` (the texture changes with `_text`, faces a moved camera, the theme colour recolours on `restyle`, the memory count returns to its start, `<img onerror>` text runs nothing, empty and very long text, a ray cast and a proxy).
- **`animate` and model clips** (G3.9b of the graphics epic 3): new `animate.ts` (`createAnimations3d`, `readAnimation3d`, `animatedProperties3d`, `ANIMATION3D_NAMES`, `DEFAULT_ANIMATION_DURATION`, `PULSE_GROWTH`, `BOB_HEIGHT`): a node's `animate` `spin`, `bob` or `pulse` plays as one frame task of the scene's scheduler over the node's own values (not a camera's, not a `repeat3d` copy's), writing nothing. New `clips.ts` (`ModelClips`, `unknownClipReason`): a `model` plays the GLB clip `animation` names (the first when unset) with an `AnimationMixer` while `playing` is true, pauses on `playing: false`, and tells an unknown name once to `onIssue` (`unknown_clip: ...` naming the file's clips); the mixers advance only in the scheduler's frames while a clip plays. Reduced motion (on create and `setReducedMotion`) stops both and shows each clip's first frame. `ModelHooks` gains `onModel`; `Scene3dInfo` gains `animations` and `clips`; `drawn()` does not wait for them. New fixture `test/fixtures/box-clips.glb` (`clipsGlb()` of `make-fixtures.ts`, `clipsFixture` in `test/globalSetup.ts`). The chunk grows by 3,751 bytes gzipped.
- **Press and hover** (G3.8 of the graphics epic 3): new `Scene3dOptions.onEvent` (`Scene3dEvent` `{ name: 'press' | 'hover', shape, key, point }`). A primary-button click on an `interactive: true` node (or inside one) is a press, from a ray cast at the release: within 4 CSS pixels (`PRESS_SLOP`) and with no camera move between (`PressGesture`), so a drag that turns or pans the camera is not one; a press on empty space or a node that is not interactive raises nothing. A pointer move with no button raises `hover` once when it enters an interactive node; the cursor is `pointer` over one, and `move` with controls on. A `repeat3d` copy's events carry `<repeat>.rows.<recordKey>` and the record key. New proxy layer (`proxies.ts`, `createProxies`): a `button` per shown interactive node in tree order, named by `_label`, with `data-shape-path` and `data-shape-kind`, placed every frame over the node's projected bounds (`screenBox`), `opacity: 0` and `pointer-events: none`; Enter, Space and a click press it at the centre of the node's bounds. `elementOf(path)` now gives that button (the test that it gave nothing changes with it). New exports: `PRESS_SLOP`, `PressGesture`, `interactiveNodes`, `isShownNode`, `screenBox`, `ScreenBox` (`interaction.ts`), `createProxies`, `Proxies`, `ProxyHooks`, `Scene3dEvent`. Tests: `src/interaction.test.ts`, `test/interaction.browser.test.ts`.
- **Textures from files** (G3.7c of the graphics epic 3): a `mesh`'s `material.map` (a png, jpeg, gif or webp file reference) is read with the scene's `readFile`, decoded with `createImageBitmap` on a `Blob` (`MAP_BITMAP_OPTIONS`, `imageOrientation: 'flipY'`; no `blob:` URL) and drawn as an sRGB `Texture` with `flipY = false`, tinted by the material's `color`. New module `textures.ts`: `mapSource`, `MapTextures` (one texture per mesh, or per `repeat3d`, whose instances share the first copy's map), `TEXTURE_FILE_TYPES`, `MAP_BITMAP_OPTIONS`. A map of another type (`unsupported_type`, not read), a failed read (its code) and bytes that do not decode (`not_an_image`) are `file` issues, told once per value, and the mesh draws its colour only. `Scene3dIssue` gains `node` (`mesh` or `repeat3d` for a map; unset for a model). `drawn()` waits for maps being read (`SceneGraph.loading`); `info()` gains `maps` `{ loading, loaded }`. The same file again reads nothing; another file, no map or the node going aborts the read, frees the texture and closes its bitmap. Tests: `src/textures.test.ts` (Node), `test/texture.browser.test.ts` (red at the top-left of a plane facing the camera and an sRGB grey, `drawn()` waiting, a missing file, bytes that are no picture and a GLB-typed reference drawing the colour with their issues, memory back after a changed, removed and gone map, a repeat sharing one texture).
- **`repeat3d` as instanced meshes** (G3.6 of the graphics epic 3): a `repeat3d` draws the copies of its row (its `children`, `mesh` nodes at `<repeat>.rows.<recordKey>` bound by the `scene3d` component) as one `InstancedMesh` with the first copy's geometry and material and each copy's own matrix (`position`, `rotation`, `scale`; hidden at scale zero) and colour (`material.color`). New `instances.ts`, exported: `INSTANCE_CAP` (20,000), `MIN_INSTANCE_CAPACITY`, `MAX_UPDATE_RANGES`, `instanceCapacity` (buffers grow in powers of two), `instanceValues`, `instanceMatrix`, `InstanceLayout` (a slot per record key; a change of one record writes one matrix and one colour), `RepeatInstances` (uploads only the changed ranges, kept until the frame uploads them), `SHARED_ROW_PROPERTIES`, and the types `InstanceValues`, `InstanceChanges`. `flattenTree` skips a repeat's copies. `info()` gains `instances`; `hit` on an instance gives its copy, keyed by its record key, when the copy is interactive; `boundsOf` takes a copy's path. An empty set draws nothing and frees the mesh, geometry and material. Tests: `src/instances.test.ts` (capacity, layout, ranges, growth, the empty set, the ray cast's key, bounds) and `test/repeat.browser.test.ts` (a colour per instance at two pixels, one record moved and recoloured, the empty set and the last record removed, hit, memory back at its start, 10,000 instances with the time logged).
- **Transition and reduced motion** (G3.9 of the graphics epic 3): a node whose `transition` is an object eases `position`, `rotation`, `scale`, a mesh's `material.color` and `material.opacity`, a light's `intensity` and a camera's `position` and `target` when the tree changes them (`TWEENED_CHANNELS`); other properties, hidden nodes and `repeat3d` copies jump, and a change during a tween starts from the value on screen. New modules: `scheduler.ts`, a copy of the component library's drawing scheduler with its tests (`createScheduler`, `parseDuration`, `parseEasing`, `cubicBezier`, `durationToken`, `easingToken`, `isReducedMotion`, `DEFAULT_DURATIONS`, `DEFAULT_EASINGS`, ...), and `motion.ts` (`createMotion3d`, `timingOf`, `formatRgb`), which hands the scene the tree with the running values; each frame syncs that tree and draws. Token names (`fast`, `standard`, ...) are resolved by the renderer when a tween starts, through the new `readToken` option (default: the host's computed style; unset tokens take the shipped values). Frames are asked for only while something moves; `drawn()` waits until every tween has ended; `info()` gains `tweens`. With reduced motion every change jumps, and `setReducedMotion(true)` ends running tweens at their targets. Controls: a gesture ends the camera's tweens at once before it reads the view (`CameraControlsHost.onGestureStart`), a state change of the camera during a gesture jumps, the camera a gesture writes is not tweened back, and a state change after a gesture tweens from the view it left (`CameraControls.gesturing` and `holding()`). `createColorConverter` keeps at most 512 colours, since a colour tween makes one per frame. The chunk is 178,266 bytes gzipped with G3.6's work in progress (gate 193,004). Tests: `src/scheduler.test.ts` (the copy), `src/motion.test.ts` (fake clock), `test/scheduler.fixture.test.ts` with `test/fixtures/scheduler.fixture.json` (committed in both repositories: easings, durations in `ms` and `s`, tweens with times and values), `test/motion.browser.test.ts` (a box crosses the centre frame by frame and ends on the right, reduced motion jumps in one frame, a switch to it ends a tween, no frame at rest, an orbit gesture ends the camera's tween and a write during it jumps, a written camera is not tweened back, a camera moved after a gesture tweens).
- **3D, release 3A: documentation, publish order and pack check** (G3.11 of the graphics epic 3, first pass): the README says what release 3A draws and what is not built yet (`repeat3d`, `label3d`, `press` and `hover`, `transition`, `animate`, `material.map`), gives the chunk's measured size (677,638 bytes minified, 173,232 gzipped; gate 193,004), how a custom host serves and names the chunk (`load.chunks`, `ui-load-3d`, the `load3d` hook), the supported and refused GLB files in short, the headless WebGL note (no launch arguments, the first page's lost contexts, 16 contexts a page) and a release checklist: the publish order (`@punyts/stateui-3d`, `@punyts/stateui-components`, `@punyts/stateui-app`, `@punyts/stateui-mcp`), the lockfile rule (regenerate `package-lock.json` with npm 10) and the `npm pack --dry-run` check. New `test/pack.test.ts` runs `npm pack --dry-run --json` (npm 10's array and newer npm's object both read): nothing outside `dist`, `package.json`, `README.md` and `LICENSE`, no sources, spike, tests or fixtures, and, after a build, `dist/index.js`, `dist/index.d.ts` and one hashed chunk with its manifest. `files` was already right; nothing else changed.
- **Orbit and pan controls, camera written on release, keyboard** (G3.8b of the graphics epic 3, release 3A): `Scene3dSettings` gains `controls` (`none`, the default, `orbit`, `pan`) and `createScene3d` the options `onCamera` (`CameraMove` `{ path, position, target }`) and `keyTarget` (default the host). New modules: `controls.ts` (`createCameraControls` with three.js's `OrbitControls`: `orbit` turns with the primary button and zooms with the wheel, `pan` only pans; the controls move a perspective rig of their own in world space and the scene draws through it, or an orthographic camera placed from it, from the start of a gesture until the state's camera changes, so the tree's objects are never moved; `keyAction`, `controlsMode`, `KEY_ROTATE_STEP` 15 degrees, `KEY_PAN_STEP` a tenth of the height, `KEY_ZOOM_STEP` 0.8) and `gesture.ts` (`CameraGestures`, `WHEEL_IDLE` 200 ms: a pointer gesture ends at its release, a wheel gesture after 200 ms idle, a key gesture when its last key is released; Escape during a pointer gesture puts the camera back and writes nothing; a change of the state's camera during a gesture is shown when it ends, and the gesture then writes nothing). Every gesture frame tells `onStatus` `pending`; at the end the active camera node's `position` and `target`, in its parent's space and rounded to 1e-6, go to `onCamera` once, and only when they changed; the default camera (no `camera` node) keeps its view in the renderer only. With controls the key target gets `tabindex="0"` (unless it has one); arrows turn (or pan), `+` and `-` zoom in `orbit` only, a step per key press. `pan` has no zoom (the wheel scrolls the page). No damping, so nothing moves after a gesture, with or without reduced motion. The chunk is 173,232 bytes gzipped with `OrbitControls` and G3.7b's `GLTFLoader` (gate 193,004). Tests: `src/gesture.test.ts` (the write timing with fake controls and a fake clock), `src/controls.test.ts` (Node), `test/controls.browser.test.ts` (a drag draws every move and writes once on release, a press with no move writes nothing, the wheel writes once 200 ms after the last turn, keys turn and zoom and write on release, pan, Escape restores, a state camera during a gesture applies at its end, `none` takes no input, back to `none`, the default camera).
- **`model` from a GLB file** (G3.7b of the graphics epic 3): a `model` draws the GLB file of its `src`. New options of `createScene3d`: `readFile` (`ReadSceneFile`, `(id, signal) => Promise<ArrayBuffer>`; the feeder reads the stored file) and `onIssue` (`Scene3dIssue`, `{ kind: 'file' | 'model', path, reason }`). New modules: `glb.ts` (`inspectGlb` refuses `not_glb`, `draco`, `meshopt`, `ktx2` and `external_uri` before parsing; `encodeGlb`, `decodeGlb`, `decodeDataUri`, `isDataUri`, `GLB_MAGIC`) and `models.ts` (`parseModel` with `GLTFLoader.parse`, no URL; the `bitmapImages` plug-in, G3.1's route (c): an embedded image's bytes in a `Blob`, `createImageBitmap` with `BITMAP_OPTIONS`, a `Texture` with `flipY = false` and the texture's sampler, and `data:` buffers decoded in place, so no `blob:` URL and no fetch; `disposeModel`; `ModelError`, with `invalid_glb` for a file three.js cannot parse). The model is added to the node's group as it is (nothing centred or scaled); the same file again reads nothing, another file or none aborts the read and frees the old model. An empty `src` is a `file` issue `no_file`, a failed read one with the read's code, a refused model a `model` issue `<code>: <detail>`; the other nodes draw. `drawn()` waits until every model being loaded has loaded or failed; `info()` gains `models` `{ loading, loaded }`; `recompile` reaches a model's meshes. The chunk is 172,815 bytes gzipped with `GLTFLoader` and G3.8b's `OrbitControls` (gate 193,004). `vitest.browser.config.ts` pre-bundles the three.js add-ons (`optimizeDeps.include`), so Vite does not reload the test page mid-run. Fixture: `test/fixtures/box.glb` (2,268 bytes) from the committed `test/fixtures/make-fixtures.ts`, given to the browser tests by `test/globalSetup.ts` (`inject('modelFixture')`). Tests: `src/glb.test.ts`, `src/models.test.ts` (Node), `test/model.browser.test.ts` (the texture red above and green below the centre with `createImageBitmap` and no `URL.createObjectURL`, placement and framing, `drawn()` waiting for the file, a missing file and an empty `src`, Draco, Meshopt, KTX2 and an external image refused while the other model draws, memory back after a changed `src` and a removed node, a file that is not a GLB).
- **Renderer hardening: environment, fog, shadows, cameras, dispose, context loss** (G3.5b of the graphics epic 3): `environment` is a lighting preset (`environment.ts`: `none`, `studio`, the default, `daylight`, `neutral`), lights and a background colour with no environment map file, kept in their own group so switching it makes no node again; `fog` (`{ color, near, far }`) draws linear fog with one reused `Fog`; `restyle()` resolves every colour again for a theme or mode switch; a light with `shadows` turns the renderer's shadow map on once, on demand (1,024 texels, `SHADOW_MAP_SIZE`); removing a node frees its geometry, material, the material's textures and a light's shadow map; `info()` gives the memory counts; on a lost WebGL context the scene stops drawing and tells the new `onStatus` option `lost`, on the restore it draws its tree again and tells `pending`, and after 5 s without a restore (`CONTEXT_RESTORE_TIMEOUT`) `failed`; a resize tells `pending` too. Removed: `ENVIRONMENT_AMBIENT`. A browser test's expected token colour changed, since `studio` now adds key lights.
- **Renderer core: camera, lights, meshes, materials, background** (G3.5 of the graphics epic 3): `createScene3d` draws a scene from the plain node tree and follows changes on demand. New modules: `diff.ts` (`diffTrees`, `flattenTree`, `changedProperties`, `sameValue`), `scene.ts` (`SceneGraph`: one three.js object per node by path, changed property by property; a node of another component, or a `light` or `camera` of another `kind`, is made again), `cameras.ts` (`activeCamera`: the first `camera` with `active: true`, else the first; `frameBounds` for the default camera that frames what is drawn; `orthographicHeight`), `geometries.ts` (`box`, `sphere`, `cylinder`, `cone`, `plane`, `torus`, `capsule` with defaults about one unit across, sizes clamped to 0..10,000, `segments` to 3..128), `materials.ts` (`MeshStandardMaterial`: `color` white by default, `metalness` 0, `roughness` 1, `opacity`, `emissive`; CSS colours of any form converted), `renderer.ts` (antialiased `WebGLRenderer` with alpha, pixel ratio at most 2, sized from a `ResizeObserver` entry with `setSize(w, h, false)`; `Scene3dError` `no_webgl` and `isScene3dError`). Lights: `ambient`, `directional` (default), `point`, `spot`, `intensity` times π (`LIGHT_SCALE`), point and spot without decay. `update(tree, settings?)` takes the scene's own `Scene3dSettings` (`background`, unset is transparent; `ambient`, an ambient light at 0.4 while `environment` is not `none`). Colours go through the new `resolveColor` option (`ColorResolver`); without it only literals resolve. Every node honours `visible` and the shared `hidden`; `model` is an empty group until G3.7b. Render on demand: one `requestAnimationFrame` per batch of changes, a resize or a restored context, none at rest; `drawn()` resolves after that frame (at once when none waits). The G3.2 unlit unit box is gone (its tests in `src/scene3d.browser.test.ts` changed with it). The chunk is 141,769 bytes gzipped (from 135,135). Tests: `src/diff.test.ts`, `src/cameras.test.ts`, `src/geometries.test.ts`, `src/scene.test.ts` (Node), `test/render.browser.test.ts` (pixels within 12 per channel: a lit box on its background, colour change and removal, lights, tokens, cameras, each geometry, frames at rest, no WebGL).
- **Package scaffold, build and chunk** (G3.2 of the graphics epic 3): the package `@punyts/stateui-3d` 0.1.0, with the build and test shape of the other libraries (`tsconfig.build.json`, `tsconfig.test.json`, `vitest.config.ts`, `vitest.browser.config.ts`). `three` 0.187.0 is pinned exactly with `@types/three` 0.187.0 (G3.1). Exports `.` (the typed API) and `./runtime-chunk/*` (`dist/runtime-chunk/`). The typed API: `createScene3d(host, options)` gives a `Scene3d` with `update(tree)`, `hit`, `boundsOf`, `elementOf`, `setReducedMotion`, `reducedMotion`, `drawn` and `dispose` (the names of the 2D `DrawingRenderer`), over a `Scene3dTree` (`NODE3D_KINDS`, `isNode3dKind`); the first renderer draws a `mesh` as an unlit box and places `group3d` children, the rest comes with G3.5. `runtime-chunk/build.ts` (`buildRuntimeChunk`, `npm run build:runtime-chunk`) bundles `src/chunk.ts` into one minified `iife`, `dist/runtime-chunk/<hash>.js` (sha256, the first 16 hex characters, as the runtime bundle) and `manifest.json` `{ hash, script }`, removing only its own earlier output. The chunk sets the one global `__stateui3d` (`{ version, createScene3d }`, `GLOBAL_NAME`, `Stateui3dGlobal`) and removes the `window.__THREE__` three.js sets unless the page had one. Tests: `runtime-chunk/build.test.ts` (hashing, own output only, one file, a gzip gate 15% above G3.1's 167,830 bytes), `test/package.test.ts` (no `@punyts/stateui-*` runtime dependency, `three` pinned with its types, the version), `src/scene3d.browser.test.ts` and `test/chunk.browser.test.ts` (only `__stateui3d` is added to a page).
