# @punyts/stateui-3d

Draws StateUI 3D scenes (`scene3d` and its nodes) with three.js. The StateUI runtime loads it as a second script, only for apps that use a scene.

The shapes of `scene3d` and its nodes (`state.json` files, shape tier) live in `@punyts/stateui-components`, where the catalog, the validator and `ui_component_get` read them. This package holds the renderer only, and depends on `three` and on no `@punyts/stateui-*` package, so there is no cycle with the runtime bundle (which has the component library as a dev dependency). `test/package.test.ts` fails when `package.json` gains such a dependency.

## three.js
`three` is pinned exactly (0.187.0, MIT), with `@types/three` of the same release; graphics story G3.1 chose the release and measured it: 167,830 bytes gzipped with everything the 3D epic uses, `GLTFLoader` and `OrbitControls` included, and no `eval`, `new Function` or workers. Move `three` and `@types/three` together.

## Package exports
- `.`: the typed API, for tests and other hosts.
  - `createScene3d(host, options?)` makes a `Scene3d` in `host` (an element): a canvas that follows the host's size (a `ResizeObserver`; written through CSSOM, and `setSize(w, h, false)` writes no `style` attribute), an antialiased `WebGLRenderer` with an alpha channel and a pixel ratio of at most 2 (`MAX_PIXEL_RATIO`), and a three.js scene. It throws a `Scene3dError` with `code` `no_webgl` (`isScene3dError` also knows one made by another copy of the package, by its `name`) when the browser gives no WebGL context. Options: `reducedMotion` (default false), `resolveColor` (a `ColorResolver`, `(value) => css | undefined`: the feeder's resolver of literals and token references; without it a literal is used as it is and a token resolves to nothing) and `onStatus` (`(status: Scene3dStatus) => void`, G3.5b: told `pending` when the scene asks for a frame by itself, on a resize or a restored context; `lost` when its WebGL context is lost; `failed` when it is not back within `CONTEXT_RESTORE_TIMEOUT`, 5,000 ms).
  - `Scene3d`, named as the component library's 2D `DrawingRenderer`: `update(tree, settings?)` draws a list of `Scene3dTree` nodes and the scene's own `Scene3dSettings` (`background`, `ambient`, `environment`, `fog`; the last ones given are kept when left out, and a new scene starts with the defaults, the `studio` environment); `restyle()` resolves every colour again and draws (a feeder calls it on a theme or mode change); `info()` gives a `Scene3dInfo` (`memory` `{ geometries, textures }` from three.js's `renderer.info.memory`, `programs`, `shadowMap`, `contextLost`, `environment`); `hit(x, y)` gives the interactive node at a point of the host in CSS pixels (the first node the ray meets, or its nearest `interactive: true` ancestor); `boundsOf(path)` the node's axis-aligned bounds in scene units (`Bounds3d`, `{ min, max }`); `elementOf(path)` the element that stands for a node (none yet: the proxy buttons come with G3.8); `setReducedMotion(reduced)` and `reducedMotion`; `drawn()` resolves once the frame the last change asked for is drawn (at once when none waits; while the context is lost, after the frame drawn on its restore); `dispose()` frees the geometries, materials, textures, the environment's lights and the renderer (forcing the context loss, since a page keeps at most 16 WebGL contexts), removes the canvas and makes every later call a no-op.
  - `Scene3dTree` (`kind`, `key`, `path`, `properties`, `children`, `row`), mirroring the 2D `ShapeTree`; `NODE3D_KINDS` and `isNode3dKind` (`camera`, `light`, `mesh`, `model`, `group3d`, `repeat3d`, `label3d`); `JsonValue`, `Vector3Tuple`, `Bounds3d`, `Scene3dSettings`, `ColorResolver`. The scene keeps the tree it was given to compare it with the next one: a feeder hands a new tree and never changes one it gave.
  - The pure parts, for tests and other hosts: `diffTrees`, `flattenTree`, `changedProperties`, `sameValue` (`diff.ts`); `activeCamera`, `frameBounds`, `orthographicHeight` and `DEFAULT_FOV`, `DEFAULT_CAMERA_POSITION`, `DEFAULT_VIEW_DIRECTION`, `FRAME_MARGIN` (`cameras.ts`); `geometryParams`, `GEOMETRY_KINDS`, `MIN_SEGMENTS`, `MAX_SEGMENTS`, `MAX_SIZE` (`geometries.ts`); `materialParams` and its defaults (`materials.ts`); `ENVIRONMENT_NAMES`, `ENVIRONMENT_PRESETS`, `DEFAULT_ENVIRONMENT`, `environmentPreset`, `isEnvironmentName`, `fogParams`, `DEFAULT_FOG_NEAR`, `DEFAULT_FOG_FAR` (`environment.ts`); `lightIntensity`, `LIGHT_SCALE`, `SHADOW_MAP_SIZE` (`scene.ts`); `CONTEXT_RESTORE_TIMEOUT` (`scene3d.ts`).
  - `VERSION`, `GLOBAL_NAME` (`__stateui3d`) and `Stateui3dGlobal` (the type of that global).
- `./runtime-chunk/*`: the built chunk, `dist/runtime-chunk/<hash>.js`, and `manifest.json` (`{ hash, script }`).

## What draws (G3.5)
- **One object per node, changed property by property.** `scene.ts` keeps one three.js object per node, keyed by its path, and `update` compares the new tree with the last one (`diffTrees`): a new node is made, a node that went is removed and its geometry and material freed, a node of another component at the same path (or a `light` or `camera` of another `kind`) is made again, and a kept node gets only the properties that changed, so a changed `position` touches one object.
- **Every node** takes `position`, `rotation` (degrees) and `scale` (`[x, y, z]`), and `visible: false` or the shared `hidden: true` hides it with its children. A `group3d` places its children. A `model` is an empty group until G3.7b reads its GLB file; `repeat3d` and `label3d` are not drawn yet (G3.6, G3.6b).
- **`mesh`.** `geometry` (`geometries.ts`): `box` (`width`, `height`, `depth`, 1 each), `sphere` (`radius` 0.5), `cylinder` (`radiusTop` and `radiusBottom`, which default to `radius`, 0.5; `height` 1), `cone` (`radius` 0.5, `height` 1), `plane` (`width`, `height` 1, facing +z), `torus` (`radius` 0.4, `tube` 0.1), `capsule` (`radius` 0.25, `height` 0.5 for the middle section); no geometry or an unknown kind is a unit box. A size that is not a number of 0 or more takes its default, one above 10,000 is cut to it, and `segments` (the divisions around a round geometry; 32 by default, 48 for a torus, 16 for a capsule) is kept between 3 and 128. `material` (`materials.ts`) is a `MeshStandardMaterial`: `color` (white when unset or unresolved), `metalness` 0 and `roughness` 1 by default, `opacity` (below 1 the mesh is transparent), `emissive`. `map` is G3.7c; `castShadow` and `receiveShadow` cast and take the shadows of lights with `shadows`.
- **`light`.** `kind` `directional` (the default), `ambient`, `point` or `spot`; `color` (white by default); `intensity` (0 to 100, default 1) is multiplied by π (`LIGHT_SCALE`), so a white face turned to a directional light of intensity 1 is drawn white, where three.js's physically based lights would give 1/π of it; `position` (default `[5, 10, 5]`) and `target` (the origin) in the space of the node's parent. Point and spot lights do not fade with distance (`decay` 0); a spot's cone is 30°. `shadows: true` makes a directional, point or spot light cast shadows (an ambient light casts none) with a shadow map of 1,024 texels a side (`SHADOW_MAP_SIZE`); the first such light turns the renderer's shadow map on, once, and it stays on.
- **`camera`.** The scene draws through the active camera: the first `camera` with `active: true`, else the first `camera` in the order of the tree (`activeCamera`). It stands at `position` and looks at `target` (both in its parent's space, so a camera in a moved group moves with it), `perspective` with `fov` (degrees), or `orthographic`, which shows what a perspective camera of the same `fov` sees at its target. A scene with no `camera` gets a default perspective camera (`DEFAULT_FOV` 50°) that looks at the middle of what is drawn from in front (+z), far enough that the bounding sphere fits with 15% to spare (`frameBounds`); with nothing drawn it stands at `[0, 0, 5]` and looks at the origin.
- **The scene's own properties (G3.5b).** `environment` is a lighting preset (`environment.ts`), lights and a background colour with no environment map file: `none` (no light, no background), `studio`, the default (an ambient light of the `ambient` colour, white when unset, at 0.4, a white key light of 0.8 from `[3, 5, 8]` and a rim light of 0.3 from `[-5, 3, -8]`; background `#e9ebee`), `daylight` (a hemisphere light, sky `#cfe6ff` and ground `#6b5a45`, at 0.9 and a warm sun `#fff1d6` of 1.2 from `[4, 12, 6]`; background `#cfe6ff`) and `neutral` (a white ambient light of 0.5; background `#808080`). The preset's lights hang beside the nodes' objects, so switching the preset makes no node again. `background` is the clear colour; unset, the preset's (transparent for `none`, so the host's background shows). `fog` (`{ color, near, far }`, `fogParams`) draws linear fog: clear before `near` (1 by default), the fog's colour beyond `far` (100 by default; a `far` not beyond `near` is put one unit beyond it), the background's colour when it sets none. One fog object is kept while there is fog, so changing it compiles no program again.
- **Theme.** `restyle()` resolves every colour again when the next frame is drawn: the background, the environment's ambient colour, the fog and every node's material and light colours, making no object again; the `scene3d` component calls it on a theme or mode switch.
- **Colours** are literals or token references, resolved by the `resolveColor` option (the `scene3d` component passes the 2D paint resolver, reading the host's computed style). The CSS colour it gives is turned into a three.js colour by three.js for hex, `rgb()`, `hsl()` and names, and by drawing it once on a 1 by 1 canvas for any other form (`oklch()`, `color(srgb …)`); the alpha is dropped.
- **Render on demand.** An `update`, a `restyle`, a resize of the host or a restored WebGL context asks for one animation frame; more changes before it draw in the same frame, and nothing is scheduled at rest (a test counts the frames). A resize or a restore also tells `onStatus` `pending`, so a feeder marks itself pending until `drawn()`.
- **Dispose (G3.5b).** A node that goes frees its geometry, its material and the material's textures, and a light its shadow map; switching the environment frees the last preset's lights; `dispose()` frees all of it and the renderer, and forces the context loss. A test adds and removes 100 meshes and finds `renderer.info.memory` back at its start value.
- **Context loss (G3.5b).** On `webglcontextlost` the scene stops drawing (three.js keeps the context restorable) and tells `onStatus` `lost`; `drawn()` waits. On `webglcontextrestored` it draws the tree it holds again (three.js uploads the geometries and programs again) and tells `pending`. A context not back within 5 s (`CONTEXT_RESTORE_TIMEOUT`) tells `failed`: the `scene3d` component shows `_fallback` then; a later restore still draws. (G3.1: the first page of a newly started headless Chromium loses its contexts once.)

## Runtime chunk
`src/chunk.ts` is the entry of one classic script that sets one global, `globalThis.__stateui3d = { version, createScene3d }` (frozen), and nothing else: three.js sets `window.__THREE__`, and the chunk removes it again unless the page had one before (`src/chunkGuard.ts` runs before three.js). `runtime-chunk/build.ts` bundles it with esbuild as `runtime-bundle/build.ts` of `@punyts/stateui-app` bundles the runtime (`iife`, minified, `platform: 'browser'`, `target: 'es2022'`) and names the file after its content: sha256, the first 16 hex characters. It removes only its own earlier output from `dist/runtime-chunk` (`<16 hex>.js` and `manifest.json`). The chunk is a classic script, not a module, because the runtime frame may have an opaque origin; the server serves it beside the runtime script and the host names it by hash in the `load` message (G3.3).

A build test fails when the chunk is more than 15% above G3.1's 167,830 gzipped bytes (193,004). Today it is about 144,000 (143,569 after G3.5b; 141,769 after G3.5; 135,135 after G3.2), since `GLTFLoader` and `OrbitControls` join the chunk with the stories that use them (G3.7b, G3.8b).
