# @punyts/stateui-3d

Draws StateUI 3D scenes (`scene3d` and its nodes) with three.js. The StateUI runtime loads it as a second script, only for apps that use a scene.

The shapes of `scene3d` and its nodes (`state.json` files, shape tier) live in `@punyts/stateui-components`, where the catalog, the validator and `ui_component_get` read them. This package holds the renderer only, and depends on `three` and on no `@punyts/stateui-*` package, so there is no cycle with the runtime bundle (which has the component library as a dev dependency). `test/package.test.ts` fails when `package.json` gains such a dependency.

**Release 3A** (graphics epic 3) draws `scene3d` with `camera`, `light`, `mesh`, `model` (a GLB file from the app's file store) and `group3d`, with lighting presets, fog, shadows, orbit and pan controls whose camera is written to state on release, and readiness for `ui_screenshot`. `repeat3d` (G3.6, release 3B) draws one mesh per record as one instanced mesh. Not built yet (release 3B): `label3d` (G3.6b), which the component library does not list yet, `press` and `hover` on 3D nodes (G3.8), `animate` and model clips (G3.9b) and `material.map` textures from files (G3.7c: the shape accepts a file reference, the renderer does not read it).

## three.js
`three` is pinned exactly (0.187.0, MIT), with `@types/three` of the same release; graphics story G3.1 chose the release and measured it: 167,830 bytes gzipped with everything the 3D epic uses, `GLTFLoader` and `OrbitControls` included, and no `eval`, `new Function` or workers. Move `three` and `@types/three` together.

## Package exports
- `.`: the typed API, for tests and other hosts.
  - `createScene3d(host, options?)` makes a `Scene3d` in `host` (an element): a canvas that follows the host's size (a `ResizeObserver`; written through CSSOM, and `setSize(w, h, false)` writes no `style` attribute), an antialiased `WebGLRenderer` with an alpha channel and a pixel ratio of at most 2 (`MAX_PIXEL_RATIO`), and a three.js scene. It throws a `Scene3dError` with `code` `no_webgl` (`isScene3dError` also knows one made by another copy of the package, by its `name`) when the browser gives no WebGL context. Options: `reducedMotion` (default false), `resolveColor` (a `ColorResolver`, `(value) => css | undefined`: the feeder's resolver of literals and token references; without it a literal is used as it is and a token resolves to nothing) and `onStatus` (`(status: Scene3dStatus) => void`, G3.5b: told `pending` when the scene asks for a frame by itself, on a resize or a restored context; `lost` when its WebGL context is lost; `failed` when it is not back within `CONTEXT_RESTORE_TIMEOUT`, 5,000 ms), `readFile` (`ReadSceneFile`, `(id, signal) => Promise<ArrayBuffer>`, G3.7b: reads the bytes of a stored file for a `model`'s `src`; it rejects with an object whose `code` names the failure) and `onIssue` (`(issue: Scene3dIssue) => void`, G3.7b: told when a node cannot draw, `{ kind, path, reason }`; see Models), `onCamera` (`(move: CameraMove) => void`, G3.8b: told the active camera node's `position` and `target` once when an orbit or pan gesture that moved it ends; see Controls) and `keyTarget` (G3.8b: the element whose keys move the camera, made focusable with controls; default the host).
  - `Scene3d`, named as the component library's 2D `DrawingRenderer`: `update(tree, settings?)` draws a list of `Scene3dTree` nodes and the scene's own `Scene3dSettings` (`background`, `ambient`, `environment`, `fog`, `controls`; the last ones given are kept when left out, and a new scene starts with the defaults, the `studio` environment); `restyle()` resolves every colour again and draws (a feeder calls it on a theme or mode change); `info()` gives a `Scene3dInfo` (`memory` `{ geometries, textures }` from three.js's `renderer.info.memory`, `programs`, `shadowMap`, `contextLost`, `environment`, `models` `{ loading, loaded }`); `hit(x, y)` gives the interactive node at a point of the host in CSS pixels (the first node the ray meets, or its nearest `interactive: true` ancestor); `boundsOf(path)` the node's axis-aligned bounds in scene units (`Bounds3d`, `{ min, max }`); `elementOf(path)` the element that stands for a node (none yet: the proxy buttons come with G3.8); `setReducedMotion(reduced)` and `reducedMotion`; `drawn()` resolves once the frame the last change asked for is drawn (at once when none waits; while the context is lost, after the frame drawn on its restore; while a model's file is read or parsed, after the frame drawn once the last one has loaded or failed); `dispose()` frees the geometries, materials, textures, the environment's lights and the renderer (forcing the context loss, since a page keeps at most 16 WebGL contexts), removes the canvas and makes every later call a no-op.
  - `Scene3dTree` (`kind`, `key`, `path`, `properties`, `children`, `row`), mirroring the 2D `ShapeTree`; `NODE3D_KINDS` and `isNode3dKind` (`camera`, `light`, `mesh`, `model`, `group3d`, `repeat3d`, `label3d`); `JsonValue`, `Vector3Tuple`, `Bounds3d`, `Scene3dSettings`, `ColorResolver`. The scene keeps the tree it was given to compare it with the next one: a feeder hands a new tree and never changes one it gave.
  - The pure parts, for tests and other hosts: `diffTrees`, `flattenTree`, `changedProperties`, `sameValue` (`diff.ts`); `activeCamera`, `frameBounds`, `orthographicHeight` and `DEFAULT_FOV`, `DEFAULT_CAMERA_POSITION`, `DEFAULT_VIEW_DIRECTION`, `FRAME_MARGIN` (`cameras.ts`); `geometryParams`, `GEOMETRY_KINDS`, `MIN_SEGMENTS`, `MAX_SEGMENTS`, `MAX_SIZE` (`geometries.ts`); `materialParams` and its defaults (`materials.ts`); `ENVIRONMENT_NAMES`, `ENVIRONMENT_PRESETS`, `DEFAULT_ENVIRONMENT`, `environmentPreset`, `isEnvironmentName`, `fogParams`, `DEFAULT_FOG_NEAR`, `DEFAULT_FOG_FAR` (`environment.ts`); `lightIntensity`, `LIGHT_SCALE`, `SHADOW_MAP_SIZE` (`scene.ts`); `inspectGlb`, `encodeGlb`, `decodeGlb`, `decodeDataUri`, `isDataUri`, `GLB_MAGIC` (`glb.ts`); `parseModel`, `disposeModel`, `bitmapImages` (the `GLTFLoader` plug-in), `BITMAP_IMAGES_PLUGIN`, `BITMAP_OPTIONS`, `ModelError` (`models.ts`); `CONTEXT_RESTORE_TIMEOUT` (`scene3d.ts`); `createCameraControls`, `keyAction`, `controlsMode`, `CONTROLS_MODES`, `KEY_ROTATE_STEP`, `KEY_PAN_STEP`, `KEY_ZOOM_STEP` (`controls.ts`); `CameraGestures`, `WHEEL_IDLE` (`gesture.ts`); `INSTANCE_CAP`, `MIN_INSTANCE_CAPACITY`, `MAX_UPDATE_RANGES`, `instanceCapacity`, `instanceValues`, `instanceMatrix`, `InstanceLayout`, `RepeatInstances`, `SHARED_ROW_PROPERTIES` and the types `InstanceValues`, `InstanceChanges` (`instances.ts`, G3.6).
  - `VERSION`, `GLOBAL_NAME` (`__stateui3d`) and `Stateui3dGlobal` (the type of that global).
- `./runtime-chunk/*`: the built chunk, `dist/runtime-chunk/<hash>.js`, and `manifest.json` (`{ hash, script }`).

## What draws (G3.5)
- **One object per node, changed property by property.** `scene.ts` keeps one three.js object per node, keyed by its path, and `update` compares the new tree with the last one (`diffTrees`): a new node is made, a node that went is removed and its geometry and material freed, a node of another component at the same path (or a `light` or `camera` of another `kind`) is made again, and a kept node gets only the properties that changed, so a changed `position` touches one object.
- **Every node** takes `position`, `rotation` (degrees) and `scale` (`[x, y, z]`), and `visible: false` or the shared `hidden: true` hides it with its children. A `group3d` places its children. A `model` draws its GLB file (G3.7b, below); A `repeat3d` draws its copies as instances (G3.6, below); `label3d` is not drawn yet (G3.6b).
- **`mesh`.** `geometry` (`geometries.ts`): `box` (`width`, `height`, `depth`, 1 each), `sphere` (`radius` 0.5), `cylinder` (`radiusTop` and `radiusBottom`, which default to `radius`, 0.5; `height` 1), `cone` (`radius` 0.5, `height` 1), `plane` (`width`, `height` 1, facing +z), `torus` (`radius` 0.4, `tube` 0.1), `capsule` (`radius` 0.25, `height` 0.5 for the middle section); no geometry or an unknown kind is a unit box. A size that is not a number of 0 or more takes its default, one above 10,000 is cut to it, and `segments` (the divisions around a round geometry; 32 by default, 48 for a torus, 16 for a capsule) is kept between 3 and 128. `material` (`materials.ts`) is a `MeshStandardMaterial`: `color` (white when unset or unresolved), `metalness` 0 and `roughness` 1 by default, `opacity` (below 1 the mesh is transparent), `emissive`. `map` is G3.7c; `castShadow` and `receiveShadow` cast and take the shadows of lights with `shadows`.
- **`light`.** `kind` `directional` (the default), `ambient`, `point` or `spot`; `color` (white by default); `intensity` (0 to 100, default 1) is multiplied by π (`LIGHT_SCALE`), so a white face turned to a directional light of intensity 1 is drawn white, where three.js's physically based lights would give 1/π of it; `position` (default `[5, 10, 5]`) and `target` (the origin) in the space of the node's parent. Point and spot lights do not fade with distance (`decay` 0); a spot's cone is 30°. `shadows: true` makes a directional, point or spot light cast shadows (an ambient light casts none) with a shadow map of 1,024 texels a side (`SHADOW_MAP_SIZE`); the first such light turns the renderer's shadow map on, once, and it stays on.
- **`camera`.** The scene draws through the active camera: the first `camera` with `active: true`, else the first `camera` in the order of the tree (`activeCamera`). It stands at `position` and looks at `target` (both in its parent's space, so a camera in a moved group moves with it), `perspective` with `fov` (degrees), or `orthographic`, which shows what a perspective camera of the same `fov` sees at its target. A scene with no `camera` gets a default perspective camera (`DEFAULT_FOV` 50°) that looks at the middle of what is drawn from in front (+z), far enough that the bounding sphere fits with 15% to spare (`frameBounds`); with nothing drawn it stands at `[0, 0, 5]` and looks at the origin.
- **The scene's own properties (G3.5b).** `environment` is a lighting preset (`environment.ts`), lights and a background colour with no environment map file: `none` (no light, no background), `studio`, the default (an ambient light of the `ambient` colour, white when unset, at 0.4, a white key light of 0.8 from `[3, 5, 8]` and a rim light of 0.3 from `[-5, 3, -8]`; background `#e9ebee`), `daylight` (a hemisphere light, sky `#cfe6ff` and ground `#6b5a45`, at 0.9 and a warm sun `#fff1d6` of 1.2 from `[4, 12, 6]`; background `#cfe6ff`) and `neutral` (a white ambient light of 0.5; background `#808080`). The preset's lights hang beside the nodes' objects, so switching the preset makes no node again. `background` is the clear colour; unset, the preset's (transparent for `none`, so the host's background shows). `fog` (`{ color, near, far }`, `fogParams`) draws linear fog: clear before `near` (1 by default), the fog's colour beyond `far` (100 by default; a `far` not beyond `near` is put one unit beyond it), the background's colour when it sets none. One fog object is kept while there is fog, so changing it compiles no program again.
- **Theme.** `restyle()` resolves every colour again when the next frame is drawn: the background, the environment's ambient colour, the fog and every node's material and light colours, making no object again; the `scene3d` component calls it on a theme or mode switch.
- **Colours** are literals or token references, resolved by the `resolveColor` option (the `scene3d` component passes the 2D paint resolver, reading the host's computed style). The CSS colour it gives is turned into a three.js colour by three.js for hex, `rgb()`, `hsl()` and names, and by drawing it once on a 1 by 1 canvas for any other form (`oklch()`, `color(srgb …)`); the alpha is dropped.
- **Render on demand.** An `update`, a `restyle`, a resize of the host or a restored WebGL context asks for one animation frame; more changes before it draw in the same frame, and nothing is scheduled at rest (a test counts the frames). A resize or a restore also tells `onStatus` `pending`, so a feeder marks itself pending until `drawn()`.
- **Dispose (G3.5b).** A node that goes frees its geometry, its material and the material's textures, and a light its shadow map; switching the environment frees the last preset's lights; `dispose()` frees all of it and the renderer, and forces the context loss. A test adds and removes 100 meshes and finds `renderer.info.memory` back at its start value.
- **Context loss (G3.5b).** On `webglcontextlost` the scene stops drawing (three.js keeps the context restorable) and tells `onStatus` `lost`; `drawn()` waits. On `webglcontextrestored` it draws the tree it holds again (three.js uploads the geometries and programs again) and tells `pending`. A context not back within 5 s (`CONTEXT_RESTORE_TIMEOUT`) tells `failed`: the `scene3d` component shows `_fallback` then; a later restore still draws. (G3.1: the first page of a newly started headless Chromium loses its contexts once.)

## Models (G3.7b)
- **Supported files, in short.** A binary glTF 2.0 file (`.glb`, `model/gltf-binary`) of at most 10 MiB (the file store's limit), uploaded to the app's file store (G3.7 checks the magic number, the version and the length on upload), with its buffers and its PNG or JPEG textures embedded. Refused: `.gltf` files (refused on upload), Draco, Meshopt and KTX2 compression, and buffers or images outside the file; WebP and AVIF textures draw without their image. Details below.
- **From the file store, with no URL.** A `model`'s `src` is a file reference (`{ id, name, size, type }`, `model/gltf-binary`). The scene reads its bytes with the `readFile` option by the reference's `id` (the `scene3d` component reads them through the host's `ui-file-read`, since the chunk has no access to the store or the host), checks them (`inspectGlb`) and parses them with `GLTFLoader.parse` (`parseModel`), so nothing is fetched. The file's default scene is added to the node's group as it is: nothing is centred or scaled, and the node's `position`, `rotation` and `scale` place it. Its animation clips are kept for G3.9b (`userData.animations`).
- **Embedded textures (G3.1's route (c)).** The `bitmapImages` plug-in loads each image from its `bufferView` (or a base64 `data:` URI), wraps the bytes in a `Blob` and decodes them with `createImageBitmap` (`imageOrientation: 'none'`, `premultiplyAlpha: 'none'`, `colorSpaceConversion: 'none'`, `BITMAP_OPTIONS`), and makes the `Texture` with `flipY = false` and the texture's sampler. Neither `img-src` nor `connect-src` governs that, so the frame's policy (`img-src data:`, `connect-src 'none'`) needs no `blob:`. A `data:` buffer is decoded the same way. Textures named through `EXT_texture_webp` or `EXT_texture_avif` are taken by the loader's own plug-ins and draw without their image.
- **Refused models.** A file that is not a GLB of version 2 whose header length is its size (`not_glb`), a compressed model (`draco`: `KHR_draco_mesh_compression`; `meshopt`: `EXT_meshopt_compression` or `KHR_meshopt_compression`; `ktx2`: `KHR_texture_basisu` or an `image/ktx2` image; they need workers or WebAssembly, which the policy refuses), one with a buffer or image outside the file (`external_uri`: a `uri` that is not a `data:` URI) and one three.js cannot parse (`invalid_glb`) draw nothing and are told to `onIssue` as `{ kind: 'model', path, reason }`, the reason being the code and what in the file it is about (`draco: it uses KHR_draco_mesh_compression`); the `scene3d` component reports `SUI-RUN-3D`. An empty `src` (`no_file`) or a failed read (its code: `not_found`, `offline`, ...; `offline` too without `readFile`) is `{ kind: 'file', ... }`, reported as `SUI-RUN-FILE`. The other nodes draw.
- **Readiness and dispose.** `drawn()` waits until every model being read or parsed has loaded or failed and the frame after it is drawn. The same file again (same `id`) reads nothing; another file, an empty `src` or the node going aborts a read under way and frees the model drawn before: its geometries, materials, textures (and their `ImageBitmap`s) and skins (`disposeModel`; a test counts `renderer.info.memory`).
- **Fixture.** `test/fixtures/box.glb` (2,268 bytes), made by `node test/fixtures/make-fixtures.ts` and committed beside it: a unit box whose faces show one embedded PNG, red above and green below, with an unlit material. A test checks that the committed file is what the maker writes.

## Repeats as instanced meshes (G3.6)
- **What a feeder hands.** A `repeat3d` node's `children` are the copies of its row the `scene3d` component bound from its records (`expandRepeats3d` in the component library): `mesh` nodes keyed by record key at `<repeat>.rows.<recordKey>`. They are not nodes of the scene: `flattenTree` skips them, and the repeat compares them itself (`RepeatInstances`, `instances.ts`). The repeat is a group, so its own `position`, `rotation` and `scale` place every instance.
- **One `InstancedMesh`.** The geometry and the material (white, so the instance colour is the colour) are made from the first copy and shared; each copy has its own matrix (`position`, `rotation`, `scale`; a hidden copy, `visible: false` or `hidden: true`, is drawn at scale zero) and its own colour (`material.color`, resolved like any colour, white when unset). The other properties of the row (`SHARED_ROW_PROPERTIES`: `geometry`, the rest of `material`, `castShadow`, `receiveShadow`) are the first copy's for all; the component reports copies that differ there (`SUI-RUN-DRAW`). `transition` does not ease the instances.
- **Buffers.** Capacity grows in powers of two from 16 (`instanceCapacity`) up to `INSTANCE_CAP`, 20,000, and shrinks only when the count falls to a quarter of it; a new size makes a new `InstancedMesh` and frees the old one. Within a size, `InstanceLayout` keeps each record at its slot (a removed record's slot takes the last instance), and a change of one record writes one matrix and one colour and uploads only those ranges (`addUpdateRange`, at most `MAX_UPDATE_RANGES`, 64, then the whole buffer); ranges written before one frame are all kept until it uploads them.
- **Empty.** No copies (an empty or missing record set, or the last record removed) draws nothing and frees the mesh, its geometry and its material, so `info().memory` goes back to where it was; `info().instances` counts the instances drawn.
- **Picking.** `hit(x, y)` on an instance gives its copy (`key` the record key, `path` `<repeat>.rows.<recordKey>`) when the copy is `interactive: true`, from the instance index of the ray cast; `boundsOf(<repeat>.rows.<recordKey>)` gives that instance's bounds. G3.8 builds press and hover on these.
- **Time.** 10,000 instances, each its own colour, draw in about 40 ms on SwiftShader in headless Chromium, and a change of one of them in about 100 ms (`test/repeat.browser.test.ts` logs both).

## Controls (G3.8b)
- **Modes.** The `controls` setting is `none` (the default: the scene takes no pointer, wheel or key input), `orbit` (the primary pointer button turns the camera around its target, the wheel zooms; no pan) or `pan` (every pointer button moves the camera and its target together; no turn, no zoom, so the wheel scrolls the page). They use three.js's `OrbitControls` on the canvas (`controls.ts`, `createCameraControls`), with no damping, so nothing moves after a gesture, with or without reduced motion.
- **The renderer moves, state is written once.** From the start of a gesture the scene draws through the controls' own camera (a perspective rig in world space, or an orthographic camera placed from it, with the lens of the tree's camera), on every frame of the gesture, and the tree's camera objects are never moved. Each gesture frame tells `onStatus` `pending`. When the gesture ends (`gesture.ts`, `CameraGestures`: the pointer's release, the wheel idle for 200 ms, `WHEEL_IDLE`, or the release of the last key held) the active camera node's `position` and `target`, in its parent's space, go to the `onCamera` option once (`CameraMove` `{ path, position, target }`), and only when they changed; the feeder writes them. The scene keeps the view until the state's camera changes (the feeder's own write among them). The default camera (a scene with no `camera` node) has nowhere to be written and keeps its view in the renderer only.
- **State during a gesture.** A change of the active camera's properties that arrives during a gesture is not drawn until the gesture ends; then the state's camera is drawn and the gesture writes nothing.
- **Keys.** With controls the `keyTarget` option (default the host) gets `tabindex="0"` (unless it has a `tabindex`), and its keys move the camera (`keyAction`): in `orbit` the arrow keys turn by 15° (`KEY_ROTATE_STEP`) and `+` and `-` scale the distance to the target by 0.8 and 1.25 (`KEY_ZOOM_STEP`); in `pan` the arrow keys move by a tenth of the scene's height (`KEY_PAN_STEP`). A step per key press (a held key repeats), written when the keys are released, or when the focus leaves. Keys are ignored during a pointer gesture. Escape anywhere during a pointer gesture puts the camera back where it started, and the rest of the gesture is ignored and writes nothing. Back to `none`, the listeners and the `tabindex` go and the tree's camera draws again.

## Transition (G3.9)
- **What eases.** A node whose `transition` is an object (`{ duration, easing }`, as for 2D shapes) eases the channels `TWEENED_CHANNELS` names when the tree changes them: `position`, `rotation` and `scale` of every node, a mesh's `material.color` and `material.opacity`, a light's `intensity`, and a camera's `position` and `target`. Other properties, hidden nodes and the copies of a `repeat3d` jump. A change during a tween starts from the value on screen.
- **Timing.** `duration` is a number of milliseconds, a string in `ms` or `s`, or a token name (`fast`, `base`, `slow`); `easing` is a token name (`standard`, the default, `enter`, `exit`), a `cubic-bezier(...)` or `linear`; the component library's validator accepts only the names and milliseconds up to 60,000. The renderer resolves the names itself when a tween starts, through the `readToken` option (`(name) => string | undefined`, a custom property such as `--ui-motion-duration-slow`); by default it reads the host's computed style, so a theme set on an ancestor applies. Unset tokens fall back to the shipped values (`DEFAULT_DURATIONS`, `DEFAULT_EASINGS`).
- **Scheduler.** `scheduler.ts` is a copy of the component library's `src/shared/drawing/scheduler.ts` (this package depends on no `@punyts/stateui-*` package), with its tests; `test/fixtures/scheduler.fixture.json` is committed in both repositories and `test/scheduler.fixture.test.ts` asserts it on each side, so the copies cannot drift. Change them together. `motion.ts` (`createMotion3d`) keeps one tween per node and channel on it and hands the scene the tree with the running values. Frames are asked for only while something moves; `drawn()` waits until every tween has ended; `info().tweens` counts the running ones.
- **Reduced motion.** With `reducedMotion` (or `setReducedMotion(true)`, which also ends running tweens at their targets) every change jumps. The component library sets it from `--ui-motion-duration-base` parsing to 0 (the shipped `reduced` overlay sets `0ms`), on mount and on a `motion` overlay change.
- **Gestures.** An orbit or pan gesture ends the camera's tweens at once, where they were going, before the controls read the view; a state change of the camera during the gesture jumps. The camera a gesture writes through `onCamera` does not tween when the state gives it back. A camera that state moves after a gesture tweens from the view the gesture left.

## Runtime chunk
`src/chunk.ts` is the entry of one classic script that sets one global, `globalThis.__stateui3d = { version, createScene3d }` (frozen), and nothing else: three.js sets `window.__THREE__`, and the chunk removes it again unless the page had one before (`src/chunkGuard.ts` runs before three.js). `runtime-chunk/build.ts` bundles it with esbuild as `runtime-bundle/build.ts` of `@punyts/stateui-app` bundles the runtime (`iife`, minified, `platform: 'browser'`, `target: 'es2022'`) and names the file after its content: sha256, the first 16 hex characters. It removes only its own earlier output from `dist/runtime-chunk` (`<16 hex>.js` and `manifest.json`). The chunk is a classic script, not a module, because the runtime frame may have an opaque origin; the server serves it beside the runtime script and the host names it by hash in the `load` message (G3.3).

**Size.** A build test (`runtime-chunk/build.test.ts`, gzip level 9) fails when the chunk is more than 15% above G3.1's 167,830 gzipped bytes (193,004). At release 3A it is 677,638 bytes minified and 173,232 gzipped, with `GLTFLoader` (G3.7b) and `OrbitControls` (G3.8b) in it (143,569 after G3.5b; 141,769 after G3.5; 135,135 after G3.2). The runtime bundle does not grow: an app without a `scene3d` never requests the chunk.

### Loading it in a custom host
The StateUI MCP server does all of this; another host that shows the runtime page does the same (G3.3):
1. Serve `dist/runtime-chunk/<hash>.js` beside the runtime script, at `./<hash>.js` relative to the runtime page (the frame's `script-src 'self'` allows it; nothing else in the frame's policy changes), with an immutable `Cache-Control`, since the name is the content's hash. Read the hash from `@punyts/stateui-3d/runtime-chunk/manifest.json` (`{ hash, script }`); the MCP server resolves it as an optional dependency and starts without it.
2. Name it in the runtime's `load` message: `chunks: { "3d": "<hash>" }` (16 lower-case hex characters; another name or another form drops the `load` as invalid). Without `chunks` the runtime has no `load3d` hook.
3. The runtime then answers a scene's `ui-load-3d` event (bubbling, composed, detail `{ respond(promise) }`) with its `load3d` hook: the first call adds one `<script src="./<hash>.js">`, resolves with `globalThis.__stateui3d` once it ran, and rejects with `load_failed`, `script_error` or a 15 s `timeout`; later calls get the same promise. An unanswered event or a rejected load shows the scene's `_fallback` text and reports `SUI-RUN-3D` (`no_chunk`, or the load's code).

The message, the hook and the event are documented in the `@punyts/stateui-app` README (Preview runtime and message protocol, 3D chunk), and the scene's side in the `@punyts/stateui-components` README (`scene3d`).

## Headless WebGL
Playwright 1.61.1's headless Chromium (149) draws WebGL2 on SwiftShader with **no launch arguments** (G3.1), so the MCP server's `ui_screenshot` captures scenes as they are; a test in `@punyts/stateui-mcp` fails when the preview browser loses WebGL2. Software rendering differs a little between machines, so the pixel tests allow 12 per colour channel. Two limits of Chromium matter: the first page after the browser starts loses its WebGL contexts once and gets them back about a second later (the scene draws again on the restore and stays `pending` until then, so a screenshot waits), and a page keeps at most 16 live WebGL contexts, so with more scenes the oldest show `_fallback` (`ui_validate` warns past 16 scenes a page, `SUI-DOC-LIMIT-SCENES`). A browser without WebGL shows `_fallback` and reports `SUI-RUN-3D` `no_webgl`.

## Release checklist
The packages are published from their own repositories, at the versions in their `package.json` files; while the graphics epics run they all stay at 0.1.0 and collect their changes under `## Unreleased` in their CHANGELOGs, which become the release's section when it is cut.
1. **Build and test.** From the workspace root, `npm run mcp:build`; in each package `npm test` (and `npm run test:browser`, `npm run typecheck`).
2. **Check what is published.** In this package, after the build: `npm pack --dry-run`. The list must show `dist` with `dist/runtime-chunk/<hash>.js` and `dist/runtime-chunk/manifest.json`, `package.json`, `README.md` and `LICENSE`, and no `src`, `spike`, `test`, fixture (`.glb`) or `runtime-chunk/build.ts` files (`files` is `["dist"]`). `test/pack.test.ts` checks the same list in `npm test`.
3. **Publish in dependency order**, each after the one before is on the registry:
   1. `@punyts/stateui-3d` (depends on no punyts package);
   2. `@punyts/stateui-components` (its browser tests draw through this package's chunk; it has no runtime dependency on it);
   3. `@punyts/stateui-app` (its runtime bundle is built with the component library);
   4. `@punyts/stateui-mcp` (takes `@punyts/stateui-3d` as an optional dependency and serves its chunk).
4. **Lockfile.** A changed dependency in any `package.json` needs `package-lock.json` regenerated with **npm 10**, which CI uses, not a newer local npm, so CI's `npm ci` reads the lockfile it expects: `npx npm@10 install --package-lock-only` at the root of the workspace (and of ai-minion, whose `libraries/<name>` link to these repositories).
